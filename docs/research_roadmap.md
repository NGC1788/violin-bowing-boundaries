# 연구 단계와 검증 기준

서버 환경 설치는 연구의 준비 단계다. 새 방법론의 성능 개선이나 논문 게재를 보장하지 않는다. 현재 저장소에는 아래 모델 학습 및 실제 계측 파이프라인이 아직 없다.

## 준비 및 데이터 감사

1. Ubuntu에서 GPU와 패키지를 실제 실행하고 환경·commit을 기록한다.
2. 공개 기계 데이터의 원문 설명, 현 종류, 속도·힘·접촉 위치, 신호 단위와 시간축을 확인한다.
3. 선택한 아카이브를 검사하고 일부 구간부터 읽는다. CSV chunk 처리와 Parquet 변환을 구현한다. 변환 전후 행 수·시간·단위·결측치·수치 일치를 확인한다.
4. 교정된 힘 센서, 영상의 실제 속도/접촉 위치, 오디오의 시간 동기화를 파일럿으로 검증한다. 계측 자체가 검증되기 전에 정량적인 실악기 힘 경계를 주장하지 않는다.

## 기준 모델과 제안 방법

- 물리 기준: 적용 가정을 명시한 Schelleng 계열 경계. 훈련 자료에서 허용된 매개변수를 보정하고 시험 자료에는 고정한다.
- 통계 기준: 유연한 분류 모델, Gaussian process 경계 추정, 측정 오차를 고려한 기존 방법. 입력 정보와 보정 자료를 공정하게 맞춘다.
- 제안 후보: 계측 불확실성, 시행 간 변동, 판정 불확실성을 구분하여 물리 사전정보와 유연한 잔차를 결합한 경계 예측. 독립 교정과 반복 측정으로 식별 가능한 항만 추정한다. 구체적 신규성은 가장 가까운 기존 방법과의 비교로 확정한다.
- 영상/음향 사전학습 모델은 단순 방법보다 계측이나 판정을 실제로 개선하는지 확인한 뒤 사용한다. CoTracker·M2D 등 외부 코드는 별도 환경에서 commit·가중치·라이선스를 확인하고 실행 검증한다.

## 엄격한 평가

1. 시행을 나눈 뒤 창을 만든다. 같은 연주/연속 신호의 창을 train/test에 흩뿌리지 않는다.
2. 세션·연주자·악기 수준의 일반화와 경계 위치·확률 보정·불확실성 범위를 평가한다. 작은 악기·연주자 표본을 전체 집단으로 일반화하지 않는다.
3. 결과 음향으로 만든 사후 판정과 연주 입력으로 예측하는 모델을 구분한다. 예측기에 결과 음향을 넣어 성능을 부풀리지 않는다.
4. 경계가 관측 범위 밖인 경우 검열 상태로 남긴다. 단일 연속 안정 구간이 존재한다고 강제하지 않는다.
5. 두 판정자의 일치도만으로 두 사람의 참 오류율을 알아낼 수 없다. 운영적 정답 정의와 민감도 분석을 사용한다.
6. 시험 자료는 최종 분석 전에 고정한다. 결과를 본 뒤 유리한 task·split·지표로 바꾸지 않는다. 제안 방법이 개선되지 않은 조건도 함께 보고한다.

9월 중순에는 환경·공개 자료 감사·계측 파일럿의 실제 진행 상황을 제시한다. 9월 말까지 계측과 분석 규칙을 파일럿으로 정리하고, 10월에는 본 수집·기준/제안 모델 비교, 11월에는 고정 시험·재현·보고서 작성을 진행한다. 계측 교정 실패 시 그 한계를 명시하고 가능한 공개 자료 분석 범위로 주장을 조정한다.
