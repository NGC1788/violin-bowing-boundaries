# evolve_v4 결과 보고 (2026-11-04)

## 한 줄 요약
AI가 직접 코드를 고쳐 가며 경쟁하는 진화형 연구 루프를 새로 만들었다. 이 루프가 찾은 새 조회 정책은 **진화 중 한 번도 보지 않은 C/D 폴더에서 필요한 파형 읽기 횟수를 3,635회에서 1,452회로 60.1% 줄였다.** 판정은 기존의 정확한 검증기가 그대로 내리므로, 틀린 판정으로 횟수를 줄이는 것은 불가능하다.

## 무엇을 풀었나 (과제 A)
11/03 보고서의 "연속 판정 문턱에서의 부분 관측 인증"과 같은 문제다. 9개 판정 규칙 가운데 하나라도 기울기 −2 법칙에 맞는지를 판단하는데, 파형을 전부 읽지 않고 **판정이 확정되는 순간 멈춘다.** 정책이 하는 일은 "다음에 어느 파형을 읽을지"를 고르는 것뿐이고, 점수는 확정까지 읽은 파형 수(적을수록 좋음)다.

## 새 방법이 왜 줄이나 (제거 실험)
기존 정책은 매번 "한 번 더 읽으면 구간이 얼마나 좁아지나"를 따져 여러 열에 조회를 흩뿌린다. 새 정책은 반대로, **규칙마다 '이 규칙이 틀렸다'는 증거(서로 겹칠 수 없는 열 두 개)를 먼저 정해 놓고 그 증거를 확인하는 데 필요한 파형만 읽는다.** 확인은 두 가지로 한다. 높은 쪽 열의 앞부분이 전부 0인지 쓸어서 보고, 낮은 쪽 열에서 양성이 둘 연속인 곳 하나를 찾는다. 라벨이 0에서 1로 바뀌는 위치는 이분 탐색으로 좁힌다.

t2는 **읽은 파형의 라벨과 공개 좌표만** 쓴다. 기존 정책과 같은 정보 조건이다.

## 루프는 어떻게 강화했나
| 이전 루프 | 새 루프 (evolve_v4) |
|---|---|
| LLM이 고정 후보 12개의 실행 **순서만** 고름 | LLM 작업자가 **실제 정책 코드를 새로 작성**하고 스스로 채점하며 다듬음 |
| 가설 하나에 하루 → 이틀간 약 6개 | 1세대 40분 동안 서로 다른 방향 4개 |
| 개선 여지를 재지 않고 시작 | **0층 관문**: 정답을 알고 사후에 줄여 본 최소치로 여지를 먼저 잼(A는 75–94% → 진행, B는 약 12% → 보류) |
| 새로움은 사후 확인 | 과학자 역할이 구조를 진단해 작업자마다 다른 방향을 주고, 작업자는 아이디어·새로움을 코드 첫 줄에 적어 제출 |
| — | 사례마다 별도 프로세스로 돌려 사례 사이 기억(라벨 재사용)을 차단, holdout은 잠금 후 1회만, 실패 포함 전 시도를 SQLite 원장에 기록 |

## 정직한 한계
- C/D 폴더는 이번 진화에서는 봉인했지만, 11/03 보고서에서 이미 쓰였다. 그래서 **완전히 새로운 독립 확증은 아니다.**
- 2세대(t2를 부모로 한 작업자 2개)는 정체했다. t6가 3,300점(−0.6%)으로 잡음 수준이었고, t5는 3,610점으로 오히려 나빠졌다. 그래서 봉인 평가를 다시 하지 않았고, 최종 결과는 t2 하나다.
- 정답을 알고 보면 ε=0.2에서 53회, ε=0.4에서 675회면 된다. 아직 줄일 여지가 있다.
- 과제 B(첼로 미래 예측)는 HGB가 이미 Markov보다 손실이 절반이다. 정답을 아는 천장까지 남은 여지가 약 12%뿐이어서, 사전 관문(20%)에 따라 LLM 예산을 쓰지 않았다.
- 비용: 작업자 1개에 약 20–35만 토큰이 들었다. 헤드리스 `claude -p`는 별도 주간 한도가 소진되어, 이 세션 안의 하위 에이전트로 대신 돌렸다.
