# 다음 단계 계획: 최적성 + 일반성 (2026-11-04 밤 작성, 미착수)

목표: "이 데이터에서 읽기 X% 감소"를 넘어서, 두 가지를 보이는 것이다.
- (1) 진화로 찾은 정책이 **정확한 최적 정책과 얼마나 가까운가**
- (2) **같은 구조를 가진 문제군 전반**에서도 통하는가

## 확인된 사실
- 고정 인증서 `possible_starts` / `certificates`와 `replay`는 크기에 묶여 있지 않다. `labels.shape = (C, K, R)`, `lower/upper = (C, 1, R)`면 열 수 C, 규칙 수 K, 파형 수 R과 무관하게 동작한다. 하드코딩은 View 주석(50, 9)에만 있다. 따라서 작은 합성 사례에도 같은 인증서를 그대로 쓸 수 있다.
- 읽기 한 번에 그 파형의 K개 라벨이 모두 공개된다. 그래서 규칙 간 단조성으로 안 읽은 칸을 추론할 수는 없다. 코랩 진화에서 가장 많이 낭비된 아이디어였다.

## 1. 작은 사례의 정확 최적해 (가장 강한 주장)
- **사례 생성기:** C=2~3, R=5~7, K=2~3(중첩 규칙)으로 작게 만든다.
  - 라벨: 열마다 뒤집히는 위치와 잡음을 가진 생성 모형으로 만든다. 규칙이 중첩되어 있으므로 칸마다 가능한 라벨 패턴은 K+1개다.
  - lower/upper: 실제 파이프라인과 같은 기울기 −2 법칙과 ε 폭으로 만든다. 만들기 전에 `law_decision_pilot_v1` 안에서 lower/upper를 어떻게 만드는지 먼저 읽고 똑같이 따른다.
- **최적 정책:** 사전분포(생성 모형) 아래에서 기대 읽기 수를 최소화하는 적응 정책을 구한다.
  - 정보 상태(읽은 칸과 그 값)에 대해 메모이제이션 DP로 계산한다.
  - 상태 수는 대략 (K+2)^(C·R)이다. C=2, R=5, K=2면 약 100만이라 가능하다.
  - 최악의 경우(minimax) 버전도 같이 낸다.
- **비교 대상:** seed(한 단계 탐욕), t2, t6, distilled_a, 코랩 최고, 일반 SBFE 기준선(적응형 탐욕, 증명수 탐색).
  - 지표: 최적 대비 비율. 사후 최소(hindsight)도 함께 보여 "적응 정책이 넘을 수 없는 차이"를 분리한다.
- **주의:** 정책 코드에 50·9 같은 상수(KSEED=8 등)가 있으면 작은 사례에서는 비교가 불공정하다. 상수를 쓰는 부분은 표시하고 따로 보고한다.

## 2. 합성 문제군으로 일반성 확인
- 생성기 매개변수(C, R, K, ε, 잡음, 열 기울기 위반률)를 바꿔 **훈련용 문제군**과 **처음 보는 문제군**으로 나눈다.
- 코랩 엔진의 적합도를 "실제 search 54사례 + 합성 훈련군"으로 바꾼다. 평가는 합성 미공개군과 봉인된 C/D에서 각 1회만 한다.
- 결과 해석: 일반 원리라면 미공개군에서도 seed 대비 감소가 유지돼야 한다. 실제 데이터에서만 좋다면 과적합이다.

## 3. 원리 증류와 설명
- 최고 프로그램을 증류한다(distilled_a 방식).
- 각 구성요소를 제거해 보며(ablation) 최적 대비 비율이 어떻게 변하는지 잰다.
- 이분 탐색과 2배씩 넓히는 탐색이 왜 줄이는지 간단한 상한을 제시한다. 예: 뒤집히는 위치가 하나면 O(log R)이다.

## 순서와 비용
1. 사례 생성기와 DP 최적해(맥, CPU)를 만든다. 먼저 C=2, R=5, K=2로 검증한다.
2. 기존 정책 비교표를 만든다.
3. 합성 문제군을 코랩 번들에 넣는다. 적합도를 바꾸면 새 캠페인으로 시작하고, 기존 a1/colab 원장은 건드리지 않는다.
4. 시작 전에 사용량을 확인한다. 작업자 1명당 약 20~35만 토큰이 들고, Pro 5시간 창에 약 3명이 한계다.
