# 공개 패키지 이식성 감사 — 2026-10-30

**판정:** Git 인덱스의 파일만 복사한 새 디렉터리에서 준비 자료 로딩과 forecast-v3 테스트 80개가 통과했다. 공식 PyPI에 모든 지정 버전이 존재한다. 최초 감사에서 발견한 PyArrow 누락은 `requirements.txt`에 `pyarrow==26.0.0`이 추가된 것을 다시 읽어 확인하여 **해결했다**. 실제 시험 환경에도 같은 버전이 설치되어 있었다.

이 감사는 과학적 성능을 재평가하거나 실험을 추가하지 않았다. 동결한 소스·규약·평가기·기존 캠페인은 수정하지 않았다.

## 실제로 확인한 것

- 작업 디렉터리를 그대로 재사용하지 않고, `git checkout-index --all --prefix …`로 **staged 파일과 이미 추적 중인 파일만** 임시 경로에 복사했다. 그 스냅샷에는 1,781개 추적 파일이 있었다.
- 새 복사본의 준비 NPZ를 별도 작업 디렉터리에서 불러왔다. 배열 크기 `(78000,60)`, 영수증 검증, SHA256 `598a6964ce7ef91c5bb6b3cde1aa37daf4b615219438f896a4dc188f0d427975`가 일치했다.
- 새 복사본에서 `python -m pytest agentic_research/forecast_v3/tests -q` 실행: **80 passed in 4.83s**. 제어기 시험은 작은 합성 자료를 사용하며, 실제 개발 자료의 모델 학습·점수 계산은 하지 않는다.
- 배포 셸 스크립트 5개가 `bash -n`을 통과했다.
- 새 복사본의 `run_forecast.sh`를 외부 작업 디렉터리에서 실행해 `init`, `freeze`, `enqueue`, `run`, `status`, `report`, `stop`, `agent`, `tick`의 `--help`가 모두 성공했다. 실제 캠페인을 생성하거나 실행하지 않았다.
- `START_HERE.md`의 준비 NPZ·규약·후보·테스트·의존성·실행 스크립트 경로는 모두 Git 인덱스에 존재했다.

사용한 Python은 이 Mac의 기존 검증 가상환경이다. **빈 가상환경에서의 재설치까지 검증했다는 뜻은 아니다.** 이 구분 때문에 공식 배포 여부를 별도로 확인했다.

## 공식 PyPI 배포 확인

아래 공식 JSON 엔드포인트에 소규모 HTTPS GET을 보내 모두 HTTP 200과 실제 배포 파일 목록을 확인했다. 요청한 버전이 없어서 대체 버전을 추정한 경우는 없었다.

| 패키지 | 확인 버전 | 공식 메타데이터 | 명시된 Python 요구 |
|---|---|---|---|
| NumPy | 2.4.6 | [PyPI](https://pypi.org/pypi/numpy/2.4.6/json) | ≥3.11 |
| SciPy | 1.17.1 | [PyPI](https://pypi.org/pypi/scipy/1.17.1/json) | ≥3.11 |
| scikit-learn | 1.9.1 | [PyPI](https://pypi.org/pypi/scikit-learn/1.9.1/json) | ≥3.11 |

`pytest>=8,<10`이라는 설치 범위 중 실제 시험 버전은 9.1.1이다. 다른 허용 버전의 성공까지 보장하지 않는다. PyArrow는 준비 NPZ로 모델을 실행할 때는 필요하지 않지만, `tests/test_data.py`가 직접 import하며 원자료 CSV 재구성에도 필요하다. 따라서 전체 시험을 안내하는 일반 설치 목록에 포함하는 것이 맞다. 위 26.0.0 버전은 실제 80개 시험 환경에 설치되어 있었다.

배포 파일 존재는 모든 OS·CPU 조합에서 설치 성공을 보증하지 않는다. 현재 검증은 Apple Silicon macOS/CPU 환경에서 이루어졌다. 새 환경에서는 설치 및 시험부터 확인하고, 실패하면 과학적 실험을 진행하지 않는다.

## 다른 컴퓨터에서 가져올 수 있는 것과 없는 것

준비 벤치마크와 영수증이 Git에 포함되어 있으므로, **같은 준비 자료로 예측 실험을 재현하는 데 원자료 CSV나 수백 GB 아카이브는 필요하지 않다.** 반대로 원자료에서 특징을 다시 추출하거나 관측기를 바꾸는 연구에는 외부의 원자료·기존 특징 CSV·추출 경로가 필요하다. 준비 자료 로딩 검증과 원자료부터의 완전 재생산은 서로 다른 범위다.

준비 자료의 원출처 다섯 Zenodo 기록에서 CC BY 4.0을 현재 공식 API로 확인했다. 저작자·DOI·라이선스·변경 내역·선택한 열두 아카이브는 `benchmarks/forecast_v3/DATA_CREDITS.md`와 `provenance.json`에 있다. 이 데이터 라이선스가 저장소 전체 소프트웨어의 라이선스를 자동으로 정하지는 않는다.

실행기는 Bash와 POSIX `fcntl`, 프로세스 그룹 기능을 사용한다. macOS/Linux가 대상이다. Windows의 기본 Python/PowerShell에서 동일하게 실행된다고 주장하지 않는다. Windows에서는 Linux 환경을 별도로 마련하고 시험해야 한다.

계정 로그인·API 키·CLI 설정·현재 Mac의 외부 무결성 잠금·Codex 앱 heartbeat는 복제하지 않는다. 새 환경에서는 새 캠페인 이름으로 동결한다. CLI 모델 호출은 각 사용자의 설치·로그인·서비스 접근에 의존한다. CLI가 없어도 수동 JSON 모드와 준비된 Python 평가기는 사용할 수 있다.

현재 계약은 2026-11-06 00:00 KST에 종료한다. 그 이후에는 새로 검토한 계약이 필요하다. 과거 계약이나 잠금 파일의 날짜를 임의로 고쳐 기존 결과에 이어 붙이지 않는다. v1/v2는 종료된 과제의 역사·감사 근거로 보존되며, 재개 대상은 forecast-v3 및 별도로 명시한 후속 연구다.

## 과학적 해석의 경계

자료는 로봇으로 켠 첼로 현의 기계 신호다. 관측기 출력 예측의 재현성이 실제 바이올린 일반화, 사람 청취 품질, 실시간 인과 예측을 보장하지 않는다. 시간 기준점은 전체 속도 궤적에서 얻었으며 개발 자료는 과거 연구에서 노출되어 있다. 준비 자료와 테스트를 다른 AI에게 전달할 수 있다는 것과 새로운 연구 결과가 독립적으로 확증되었다는 것은 다르다.

## 릴리스 전 남은 확인

최초 staged 스냅샷의 PyArrow 누락은 작업 파일에서 해결되었다. 릴리스 담당자는 수정한 설치 목록과 이 문서를 포함해 최종 stage/commit한다. 별도의 빈 가상환경 설치·OS별 wheel 호환성·외부 CLI 로그인 검증은 아직 수행하지 않았다. 동결 소스 파일의 사소한 공백 경고를 없애기 위해 소스를 수정하지 않았다.
