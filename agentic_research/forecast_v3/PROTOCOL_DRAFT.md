# 별도 후속 연구: 일관된 규칙 확률을 이용한 미래 신호 예측

> 이 문서는 초기 설계 기록이다. 이후 loader·학습기·강한 Markov 기준선·기존 coherence 보정·다중 AI 실행기와 누수 검사를 구현했고,80개 테스트를 통과한 뒤 `configs/forecast_v3.json`을 동결했다. 실제 주 지표는mean_log_loss, 선별 기준은강한기준선 대비2% 개선 및 세션별 손해0.02nats 이내다. 현재 실행·결과는 `../docs/EXECUTION_STATUS.md`가 우선한다. 아래의 ‘미구현/미동결’ 문장은 작성 당시의 이력을 보존한 것이다.

상태: **설계·수학 구성요소 검증 단계. 실측 학습 결과 없음. 아직 동결된 실험 계약이 아님.**

v1·v2 정확 질의 수 연구는 목표10% 개선이 불가능하여 종료했다. 이 문서는 그 결과를 성공으로 바꾸는 수정안이 아니라 다른 연구 질문의 준비 문서다. 규약·모형·입력 감사를 마치기 전 C/D에서 후보 점수를 비교하지 않는다.

## 질문과 실제 용도

활현 신호의 초기0.20초에서 이후0.25–0.45초의 관측 규칙 출력과 경계를 예측한다. 파형 분석의 판정 문턱을 바꾸어도 예측들이 서로 모순되지 않게 하고, 경계에 중요한 예측 오차를 학습 목표에 반영한다.

이는 “현재 특징으로 현재 규칙 라벨을 재현”하는 과제가 아니다. 미래 시점의 신호 판정을 예측해야 한다. 실제 운동 상태·좋은 연주·음질의 정답을 확보했다고 주장하지 않는다. 사용 사례는 선언한 판독 기준에 대한 미래 경고/분석 불확실성의 정량화다. 그 경고가 사용자의 의사결정에 도움이 되는지는 별도의 평가 항목이다.

## 후보의 기술적 중심

periodicity 문턱 p∈{0.7,0.8,0.9}, flyback ratio 문턱 r∈{0.3,0.5,0.7}에 대해 공유 guard/fixed가 있는 규칙은 `fixed OR (guard AND P>=p AND R<r)`다. 유한 P/R에 대해 가능한 라벨 벡터는512개 중10개다. 0 벡터와, P 문턱 행의 prefix 및 R 문턱 열의 suffix가 만드는9개 비어 있지 않은 직사각형이 해당한다. fixed=true의 전체1도 그 안에 있다.

새 구성요소 `rule_patterns.py`는 이 유한 패턴을 명시적으로 표현한다. 학습 인코더가10개 패턴의 logits를 내면 softmax를 통해 공동 분포를 만들고, 각 규칙의 주변 확률을 계산한다. 그 확률에는 P 문턱 증가 시 감소, R 문턱 증가 시 증가라는 일관성이 자동으로 성립한다. 미래 실제 벡터가10패턴 밖이면 데이터를 억지로 projection하지 않고 observer/feature 버전 불일치부터 조사한다.

비교할 학습은 동일 backbone에서 (a)독립9-head BCE, (b)공동10-pattern NLL/BCE, (c)공동 head+경계 DP 손실이다. 두 변화의 효과를 분리한다. latent categorical model, ordinal model, 미분 가능 DP는 기존 기법이다. 이 조합의 실질적인 새 기여는 엄밀한 선행 비교·제거 실험·성능·비용 검증을 통과해야 성립한다.

## 데이터 감사: 통과해야 다음으로 진행

- 입력 후보 `~/violin-rne/timeres/features/*.csv.gz`:17개,112,400stroke. 첫 개발 범위는 기존13도표78,000stroke와 일치시킨다. 파일별 해시·행 수·계열·실제 현 표본 관계를 manifest에 고정한다.
- prefix window 후보 `[0,.20]`, `[0,.10]`, `[.05,.15]`, `[.10,.20]`; target `[.25,.45]`. t가 시작점인지 중심인지 기존 추출 코드로 확인한다. `.25,.45` 값을 잘못 읽어 겹치는 창을 만들지 않는다.
- plateau_s가 미래를 보고 정해진 기준이면 ‘사전에 주어진 오프라인 landmark에서의 예측’으로 범위를 제한한다. 실시간 조기경보라 부르려면 causal landmark를 별도로 구현·검증해야 한다.
- target의 P/R/guard/fixed를 기존 observer 버전과 정확히 재구성한다. 옛 `window_audit.vector_labels`는 최신 joint-rule observer와 자동으로 같지 않다. 중복·누락·NaN·관측 중단을 조용히 제거하지 않는다.
- 입력은 prefix 안에서 계산된 force/speed/amplitude/periodicity/f0/flyback 특징과 이미 주어진 제어 변수만 사용한다. 미래 힘/특징, 전체 stroke 길이, 미래 결측, target session/파일명/순번을 입력으로 넣지 않는다.
- 입력 변경 테스트: 미래 행을 무작위로 바꾸어도 생성된 X가 비트 단위로 같아야 한다. target 변환은 해당 미래 창에만 의존해야 한다. raw prefix를 벗어난 통계로 정규화하지 않는다.
- A/B를 source, C/D를 회고적 외부 계열 개발로 사용한다. 내부 튜닝은 source의 실제 현/설치 그룹 단위로 수행한다. 모든 현재 데이터가 역사적으로 노출되었다는 사실은 유지한다.

## 반드시 비교할 것

1. source-frequency와 persistence, source-fitted Markov.
2. 같은 prefix 정보를 쓰는 logistic, controls-only HGB, snapshot HGB, history HGB.
3. 같은 작은 backbone·배치·업데이트 수·seed의 독립9-head,10-pattern head,10-pattern+boundary loss.
4. 독립 head의 사후 단조/일관성 보정과 간단한 ordinal/latent-feature 모델. 공동 head가 표현 제약만으로 얻는 이득을 분리한다.

최초 실제 비교는 최대4개 통제된 설정×3seed=12개 run으로 줄여 동결한다. 어떤4개인지는 source 내부 기준선 검사와 독립 설계 리뷰로 정한다. 최대 worker1800초, 종료일2026-11-06. 처음부터 모든 대형 모형·손실 가중치를 훑지 않는다. hyperparameter를 C/D 점수에 맞춰 바꾸려면 그것이 새 탐색임을 기록하고 기존 평가를 독립 확인이라 부르지 않는다.

## 지표와 반박

주 지표 후보는9규칙의 미래 log loss 평균이며, baseline과 같은 평가 표본을 사용한다. proper scoring을 위해 확률 clipping 상수·missing 처리·클래스 불균형 처리도 미리 고정한다. 공동 pattern NLL, Brier, 논리적 일관성 위반, entry/exit 부분집합, worst-group, 경계 rank error, calibration, runtime은 보조 지표다.

필요한 최소 개선과 허용할 그룹별 손해 한계는 source 내부 변동 및 용도에 근거해 **C/D 점수 열람 전** 숫자로 작성해야 한다. 아직 정하지 않았다. 자동화가 이 숫자를 생략하거나 사후에 채워 넣으면 안 된다. 수천의 겹친 창이나3seed로 독립 연주자 수준의 신뢰구간을 만들지 않는다.

- history HGB/persistence를 못 넘으면 새 학습 표현의 필요성 미입증.
- 공동 head의 이득이 단순 사후 보정과 같으면 특별한 architecture의 필요성 미입증.
- 경계 오차만 좋아지고 주 log loss가 나빠지면 주 결과는 실패. 좋은 지표만 남기지 않는다.
- 한 조건의 이득에만 의존하면 그 범위를 보고한다. 보편적인 모델 개선으로 쓰지 않는다.
- 논리 정합성0위반은 구성상 보장되는 성질이며 정확성·성능·novelty 점수로 대체하지 않는다.

## 바이올린 조건

현재 첼로 자료에서의 미래 예측과 공개 바이올린 자료에서의 검증은 다른 단계다. `../docs/VIOLIN_DATA_GATE.md`를 따라 Blanco2021 자료의 연속 시간 정보부터 확인한다. 데이터가 적합하지 않으면 미래창을 만들었다고 주장하지 않는다. 바이올린에서 동일한 관측 규칙을 적용할 수 없는 경우 별도의 의미 있는 불안정 예측 목표와 독립 규약이 필요하다. 단순 바이올린 음원으로 힘/β 경계를 검증할 수는 없다.

## 구현 현황을 갱신하는 위치

`rule_patterns.py`와 `tests/test_rule_patterns.py`는 첫 수학 구성요소다. loader, 학습기, source-only 전처리/검증, 봉인된 evaluator, v3 예산/변조 방지 제어는 아직 완료하지 않았다. 다음 자동 작업은 실측 입력 감사와 누수 테스트다. 승인이라는 문구만으로 이 누락된 기계를 대신하지 않는다.
